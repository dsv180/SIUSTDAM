# Инструкция для агента на рабочей машине: обновление репозитория из SIUSTDAM

> Ситуация: на этой машине уже развёрнута рабочая копия репозитория
> (синхронизация через github.com/dsv180/SIUSTDAM, remote `sync` настроен),
> и в общий репозиторий были запушены новые коммиты с домашней машины
> (ветка `pilot-patches` — русификация промптов, Snowball-токенизатор,
> эмбеддинг-конфиг). Задача агента — забрать эти изменения в локальную
> копию и интегрировать.

## 0. Перед началом

- Git-учётка уже настроена (`gh auth login` + `gh auth setup-git`),
  scope `workflow` добавлен (`gh auth refresh -h github.com -s workflow` —
  история содержит вендорский workflow-файл; без него push отклоняется).
- Шлюз памяти работает: `curl http://127.0.0.1:8420/health` → `status: ok`
  (или подняти через `C:\TDAM\gateway-service.ps1`).
- Инструменты памяти в `C:\TDAM\` (memory.mjs, хуки, конфиг) —
  соответствуют состоянию пакета-переноса.

## 1. Диагностика текущего состояния

1. Определи рабочую ветку: `git branch --show-current` (ожидается
   `pilot-patches` или рабочая ветка, ведущая от неё).
2. Зафиксируй точку старта:
   `git log --oneline -1` — записать хэш до любых операций.
3. Проверь незакоммиченные изменения: `git status --porcelain`.
   Если есть — сначала закоммить (`git add -A && git commit`) или припрячь
   (`git stash`), не терять ничего.
4. Проверь расхождение с общим репо:
   ```bash
   git fetch sync
   git log --oneline HEAD..sync/pilot-patches
   ```
   Пусто — уже актуально, работа завершена. Есть коммиты — продолжай.

## 2. Интеграция коммитов из SIUSTDAM

- Если локальная ветка не имеет собственных коммитов после точки расхождения:
  ```bash
  git merge sync/pilot-patches          # fast-forward
  ```
- Если локальная ветка имеет собственные изменения:
  ```bash
  git rebase sync/pilot-patches         # локальные коммиты поверх общих
  ```
  Конфликты — решать по месту; приоритет: русская локаль и стеммер
  из sync/pilot-patches, локальные правки рабочей машины сохранять.

## 3. Обновление зависимостей и пересборка

1. `cd MemoryCore && npm install` — зависимости могли обновиться
   (в т.ч. новая: `snowball-stemmers`).
2. Пересборка панели: `cd MemoryPanel/web && npm run build`
   (бэкенд панели раздаёт собранный фронтенд из `web/dist`).
3. Перезапуск сервисов (остановить слушателей портов 8420/8900/8123/5173,
   поднять лаунчерами):
   ```bash
   powershell -File C:/TDAM/gateway-service.ps1
   powershell -File C:/TDAM/mcp-http-service.ps1
   powershell -File C:/TDAM/panel-service.ps1
   ```
   (лаунчеры сами пропускают запуск, если порт занят живым экземпляром).

## 4. Контроль после интеграции

1. `curl http://127.0.0.1:8420/health` → `status: ok`,
   `ftsAvailable: true`, `embeddingService: true`.
2. Поиск по памяти находит регламент:
   `node C:/TDAM/memory.mjs search "регламент обновления УХ"`.
3. Панель: `http://127.0.0.1:8123` открывается, вкладки работают.
4. Иероглифов в памяти нет:
   `grep -cP "[\x{4e00}-\x{9fff}]" "%USERPROFILE%\.memory-tencentdb\memory-tdai\profiles\*\*\scene_blocks\*.md"`
   → 0 по каждому файлу.

## 5. Правила для агента при интеграции

1. Не переписывать историю и не делать force-push: рабочая копия синхронизируется
   с SIUSTDAM обычным merge/rebase.
2. Файлы с backtick'ами внутри template literal'ов (промпты l1-extraction.ts,
   scene-extraction.ts) править только через Write/генератор — bash-подстановки
   ломают экранирование (известная каскадная ошибка).
3. Сообщения коммитов — по шаблону `[pilot-patch] <суть>`; ветка `pilot-patches`.
4. Push в `origin` (вендорский TencentDB-Agent-Memory) запрещён — remote
   `origin` push URL отключён (NO_PUSH_TO_VENDOR). Пушить только в `sync`.
5. При любых изменениях в конфигах хуков или шлюза — обновить
   соответствующую инструкцию пакета, чтобы пакет оставался актуальным.
6. **Windows-пользователь ≠ владелец GitHub-авторизации**: `gh auth login`
   и credential-хранилище привязаны к профилю конкретного Windows-пользователя.
   Агент, запущенный под другим пользователем, увидит «не авторизован» и не
   сможет пушить/пуллить. Проверка: `gh auth status` от текущего пользователя —
   пусто/ошибка значит «не тот профиль». Git-операции с сетью выполнять
   от имени пользователя-владельца: `runas /user:<github-юзер> /savecred cmd`
   (и внутри — git/gh), либо просить владельца выполнить pull/push интерактивно.
   Коммиты локально (без сети) — от любого пользователя, они в общий репозиторий
   не уходят.
