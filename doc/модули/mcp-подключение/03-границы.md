# 03-Границы: перенос работы с памятью в MCP

> **Статус:** черновик на утверждение заказчика (08.11). Порядок работ —
> этапы 1–4 из 02-задания.

## Затрагивается

- **MemoryCore (шлюз)** — пилот-патч: MCP-эндпоинт POST /mcp на порту
  шлюза (перенос логики mcp-http.mjs внутрь). Помечается
  `[pilot-patch]`, носится веткой pilot-patches при обновлениях вендора.
- **mcp-http.mjs (:8900)** — живёт до приёмки вшитого MCP, затем
  демонтируется (сервис + ярлык автозапуска).
- **Хуки ZCode** (3 скрипта) — внутренний HTTP заменяется на
  MCP-клиента (initialize → tools/call); тихая деградация сохраняется.
- **CLI memory.mjs** — переводится в отладочный статус, из штатных
  правил агентов исключается.
- **Правила/скилл** (komandnaya-pamyat, AGENTS.md) — переписываются под
  MCP-инструменты.

## НЕ задевается (жёсткие границы)

- LLM-трафик: провайдеры, подписка ZCode, будущий MemoryProxy, обработка
  ответов модели.
- DSH и его коннектор — его линия, задание от заказчика.
- Панель Memory Hub (:8123) — ходит через свой API шлюза, не трогаем.
- Вьюер :8901 — вне объёма (читает профиль напрямую; судьба решается
  отдельно после этапа 3).
- Экстракционный конвейер, дедуп, эмбеддинги (Ollama bge-m3) — не
  затрагиваются.
- Данные памяти: никакой миграции данных — меняется только путь вызовов.

## Переходный период и совместимость

1. Регламент миграции живого канала: «переключить скрипты канала → стоп
   шлюза → изменения → старт → проверка» (урок 08.11 — окно утечки).
2. Фасад :8900 остаётся живым до приёмки вшитого MCP; прямой вызов
   шлюза из хуков закрывается только после приёмки переведённых хуков.
3. Откат: бэкап перед правкой; патч обратим (изолированный эндпоинт);
   хуки хранят прежнюю логику в git-истории deploy/scripts.
4. Обновления вендора: патч MCP-эндпоинта добавляется в чек-лист
   проверки после sync (как существующие патчи промптов/токенизатора).
5. Коммиты — в локальную копию pilot-patches; пуш — по указанию.

## Критерии успеха этапа 1

- Все текущие функции памяти работают через вшитый MCP-эндпоинт шлюза
  (смоки эквивалентны сегодняшним).
- Хуки ZCode работают через MCP; при остановленном шлюзе сессии не
  падают (тихая деградация).
- Панель, DSH, LLM-трафик — без изменений и без сбоев.
- Фасад :8900 ещё жив (демонтаж — после наблюдения).

## Риски

| Риск | Митигация |
|---|---|
| MCP-рукопожатие в каждом вызове хука добавляет латентность | локальный HTTP, 2-3 обмена, копейки; таймаут прежний |
| Патч ядра конфликтует при обновлении вендора | изолированный эндпоинт, ветка pilot-patches, чек-лист |
| Регресс дисциплины при переписывании правил (W7) | правила меняются после стабильного этапа 1, поэтапно |
