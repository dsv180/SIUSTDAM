# 02-Задание: онбординг-эндпоинт подключения агентов к памяти

> **Статус:** задание составлено, реализация — по решению заказчика.
> **Предыдущий:** [01-замысел.md](<01-замысел.md>). Решения по открытым вопросам
> §9 приняты по умолчанию 06.11 (имя `/connect`, markdown по умолчанию,
> контент в файлах шлюза, sha256+дата вместо /vN).

## 1. Цель

Два GET-маршрута в MemoryCore Gateway, отдающие агенту всё нужное для
самостоятельного подключения к памяти, и раздача моста как единственного
источника.

## 2. Точки интеграции (по исходникам)

| Что | Где | Как |
|---|---|---|
| Диспетчер запросов шлюза | `MemoryCore/src/gateway/server.ts` (dispatch-слой; там же `/health`) | новый вызов `handleConnectRoute(req, res, pathname, method, config)` **до** Bearer-гейта (полигон — публично; гейт К5 отложен) |
| Роутер v2 не трогаем | `v2-router.ts:487-489` — только POST и `/v2`,`/v3` | `/connect` — отдельный модуль `connect-router.ts`, чтобы не расширять контракты v2 |
| Конфиг | `MemoryCore/src/gateway/config.ts` | новая секция `connect` (см. §4) с fallback-значениями |
| Контент | новые файлы `MemoryCore/src/gateway/connect-content/{agent}.md`, `{agent}.json`, `bridge/tdai-mcp.mjs` | тексты — из адаптер-документов `doc/правила-памяти-*.md` + блоков, опробованных на пилоте 06.11 |

## 3. Маршруты (полный список)

| Маршрут | Ответ | Content-Type |
|---|---|---|
| `GET /connect/{agent}/{instance}` | инструкция (markdown) | `text/markdown; charset=utf-8` |
| `GET /connect/{agent}/{instance}?format=json` | манифест | `application/json; charset=utf-8` |
| `GET /connect/{agent}/rules` | правила дисциплины (markdown) | `text/markdown; charset=utf-8` |
| `GET /connect/bridge` | тело tdai-mcp.mjs | `text/javascript; charset=utf-8` |
| `GET /connect/agents` | список известных агентов (JSON) — для диагностики | `application/json` |

Ошибки: неизвестный `{agent}` → 404 c телом-подсказкой (список агентов);
`{instance}` на этапе 1 не проверяется (шлюз однInstансный) — эхо-значение.

## 4. Секция конфига `connect`

```yaml
connect:
  agents: ["zcode", "dsh"]          # реестр; fallback — встроенный
  # baseUrl не задаём: собирается из заголовка Host запроса
  # (полигон 127.0.0.1:8420, сервер — свой адрес, конфиг не дублируется)
```

Манифест: `gateway_url = "http://" + req.headers.host`. Оговорка: за обратным
прокси Host может искажаться — тогда поле `connect.baseUrl` переопределяет
(задел на сервер, реализуется сразу, проверка — на К5).

## 4.1 Определение типа агента (решение по вопросу заказчика 06.11)

Тип агента **не детектируется** — он декларируется и проходит сквозь весь
жизненный цикл:

1. **Онбординг**: сегмент пути `/connect/{agent}/...` — человек называет агента,
   которого подключает; ошибка → 404 со списком агентов (самокоррекция).
   Автодетект (UA/fingerprint) отвергнут: ненадёжен и не нужен, граница
   доверия — сеть и (на сервере) user_key, а не отпечаток клиента.
2. **Рабочие вызовы**: мост подписывает каждый запрос `user_id` + `session_key`.
   НАЙДЕНО: в мосте `tdai-mcp.mjs:41` префикс сессии жёстко `"zcode-"` —
   при подключении DSH сессии будут помечаться неверно. Фикс в объём 05:
   поле `agent` в конфиг моста (`~/.zcode/tdai-memory.json` / env
   `TDAI_AGENT`), `session_key = ${agent}-${userId}-…`; манифест вписывает
   `agent` в готовый конфиг-блок. Это даёт шлюзу достоверную метку агента
   в каждом вызове — основа аудита К5.

## 5. Манифест (JSON) — финальные поля

Как в 01-замысел §4.1, плюс: `bridge_sha256` считается при старте шлюза (не на
каждый запрос); `generated_at` — время старта шлюза; `manual_steps` per-agent.

## 6. Тесты (приёмочный чек-лист)

1. `curl /connect/agents` → `["zcode","dsh"]`.
2. `curl /connect/dsh/default` → текст §5.1 из 01-замысла (блок конфига —
   дословно тот, что опробован 06.11 на пилоте).
3. `curl "/connect/dsh/default?format=json"` → валидный JSON, `bridge_sha256`
   совпадает с `sha256sum` от `curl /connect/bridge`.
4. Скачанный мост: смоук initialize+tools/list (процедура 06.11).
5. Регресс: `/health`, `POST /v2/...`, `/v3/...` работают как раньше; на
   `/connect/*` POST → 404.
6. E2E: агент DSH на чистой машине (или с удалённым блоком mcp-tdam) проходит
   подключение по одному URL.

## 7. Откат

Удалить вызов `handleConnectRoute` из dispatch (одна строка) + файлы модуля.
Маршруты самодостаточны, состояние шлюза не трогают.
