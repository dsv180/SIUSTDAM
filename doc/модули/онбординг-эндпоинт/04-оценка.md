# 04-Оценка: онбординг-эндпоинт

> **Предыдущий:** [03-границы.md](<03-границы.md>)

## Трудоёмкость

| Работа | Объём |
|---|---|
| `connect-router.ts` (5 маршрутов, ошибки, Host-логика) | ~150–200 строк, один новый файл |
| Интеграция в `server.ts` dispatch | 1 вызов + импорт |
| Контент: 2 агента × (инструкция md + манифест json + правила md) | тексты 90% готовы (адаптер-документы + блок 06.11) |
| Мост в `connect-content/bridge/` | копия готового файла с фиксом |
| Тесты чек-листом (§6 задания) | curl + смоук моста + e2e на DSH |

Оценка: **одна рабочая сессия** на К1–К3; К4 (e2e на живом DSH) — зависит от
пробы подключения, которая у заказчика не подтверждена (перезапуск DSH).

## Риски

| Риск | Вероятность | Смягчение |
|---|---|---|
| Регресс dispatch при встраивании маршрута | низкая (отдельный файл, один вызов) | чек-лист §6.5 до коммита |
| Контент манифеста разойдётся с реальностью (блок конфига у DSH другой после пробы) | средняя — проба DSH ещё не выполнена | e2e (К4) до объявления маршрута рабочим; манифест правится как текст |
| Host за обратным прокси | отложено | `connect.baseUrl` |
| Двойное содержание (адаптер-документы vs манифесты) | среднее в перспективе | источник правды — манифесты; адаптер-документы сослаться на них при следующей правке |

## Стоимость неисполнения (что будет, если не делать)

Каждый новый агент отдела подключается вручную через агента-инфраструктуру с
раскопками в журнале пилота; при выносе на сервер — рассинхрон конфигураций по
машинам. При 20 агентах — существенная повторяющаяся нагрузка.

## Вердикт

Реализуемо малыми силами, без изменений архитектуры, с чистым откатом.
Блокирующего нет. Рекомендация: исполнять после подтверждения пробы DSH
(перезапуск + `mcp__tdam__*`), чтобы контент манифеста вносился уже проверенным.
